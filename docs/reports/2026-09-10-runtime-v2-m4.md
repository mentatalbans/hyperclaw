## Gate mapping and behavior

- Other-session/workspace records cannot displace matching permitted records from the top five: SQL-filtered candidate tests plus the frozen scope fixture.
- Corrections/forget survive restart and update retrieval atomically: real Store rollback/concurrent-correction tests and public daemon restart tests.
- Provenance and authority remain separate: model-selected identity fields are rejected; records carry actual source run/version; retrieved instructions do not grant file-write or command authority.
- Real fresh-store retrieval: the live tool demonstration above reads an opaque seeded marker.
- Explicit memory only: an ordinary reply to a “remember” prompt without a memory tool call creates no fact. No keyword extraction or self-rated learning remains.

Mutation requires the record's exact scope. Session searches include private plus shared workspace facts; workspace searches include shared facts only. Session reset retains explicit memory. Forget excludes a record from retrieval while preserving versions, receipts and old conversation archives. Tool results are bounded whole JSON records; storing text does not verify its truth. Historical accepted run/schedule allowlists are preserved by the additive schema 4 migration; new requests offer all nine closed-catalog tools.

Process tests send SIGKILL on both sides of the actual memory/receipt COMMIT and restart twice through ordinary production startup. The pre-commit kill leaves no fact; the post-commit kill preserves exactly one fact/version and its immutable receipt. Neither is replayed. Injected receipt-event failure rolls back the memory/index changes as well.
