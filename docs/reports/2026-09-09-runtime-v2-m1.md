## Run/result/replay walkthrough

Use a fresh disposable directory and the already-installed model. In one terminal:

```sh
hyperclaw --root /tmp/hyperclaw-m1-demo init
hyperclaw --root /tmp/hyperclaw-m1-demo serve --port 0
```

In another:

```sh
hyperclaw --root /tmp/hyperclaw-m1-demo chat 'Describe a paper kite in one sentence.' --detach
hyperclaw --root /tmp/hyperclaw-m1-demo run inspect RUN_ID
hyperclaw --root /tmp/hyperclaw-m1-demo run events RUN_ID
hyperclaw --root /tmp/hyperclaw-m1-demo run events RUN_ID --after SEQ
hyperclaw --root /tmp/hyperclaw-m1-demo session reset SESSION_ID
```

Run inspection includes the session ID under `request.session_id`. Events preserve committed sequence numbers and end with one `run.finished` carrying status and `verification=not_requested`. Stop only this disposable daemon with Ctrl-C in its own terminal. The automated tests exercise this flow, real restart/crash, and live answers.

## Review corrections and limits

Final independent review found no remaining important findings and passed both specification and quality checks. Task reviews found and verified fixes for private permissions on adopted empty roots, retrying a corrected future migration without overwriting backups, transport deadlines crossing generator yields, final usage unknown counts, duplicate append at cancellation, cancellation awaiting worker reconciliation, canonical port-80 Host/Origin, and malformed metadata during teardown. Regressions first reproduced each failure.

M1 intentionally has no tools, images, external writes, scheduling, long-term memory, skills, MCP, web assets, or Telegram. Complete model text is response completion; general answers are not independently verified actions. There is no automatic retry, provider fallback, model download, or legacy importer. Default root is `~/.hyperclaw-v2`, default listener `127.0.0.1:8011`; the private bearer token stays in `root/token`.

M2's execution-policy/Docker ownership gate, M3's effect recovery/scheduling, M4's memory baseline, M5's MCP/skills, and M6's clients remain outstanding. No M2 implementation or service adoption was performed.
