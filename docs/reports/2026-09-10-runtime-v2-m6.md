## Delivered behavior

The web client provides session/run history, streamed chat, cancellation, reset, exact-invocation approvals, receipts, explicit tools and opt-in admitted skills. Token entry is cleared on connection; credentials stay in page memory and authenticated fetch carries event streams. Only the three fixed shell assets are public, after Host/Origin checks. Older history and hash recovery work beyond the first page. Connection, selection and observer ownership prevent stale completions from replacing current navigation or logout. Ambiguous sends retain the same frozen request and explicit retry identity. Optional discovery failures show actionable warnings while core chat remains available; missing admission cannot enable MCP. An embedded static favicon prevents browser fallback errors, with `data:` permitted only for images.

Telegram is disabled by default, owned by daemon lifespan, and uses the same Runtime and policy. Explicit chat/sender authorization precedes attachment IO. The private fixed token file has descriptor, ownership, permission, link and size checks. The fixed-origin HTTP transport rejects redirects/encoded bodies and caps raw JSON/photo bytes. Supported input is text or one photo with an optional caption; whitespace-only captions use the image prompt. Telegram cannot grant permissions, decide approvals or auto-admit MCP/skills.

Schema 7 adds Store-owned bot/chat/topic/sender session mappings, durable update/cursor records and phase-specific delivery records. The complete prepared request survives reservation/submit/binding gaps; reconciliation checks the exact accepted request. Delivery commits intent before HTTP, validates success evidence and preserves uncertain outcomes without blind retries. Revocation prevents pending delivery. Authenticated GET `/v1/telegram` and the CLI expose bounded sanitized status.

The 88-case Telegram suite includes two independent actual SIGKILL/restart trials at each reserve-before-submit, submit-before-bind and send-before-receipt boundary. Local HTTP-peer and SQLite evidence show one session/run, durable offsets and no accepted-run reexecution or blind resend. Additional cases cover revocation after SIGKILL, local approvals with continued intake, schema-6 preservation, cancellation settlement, malformed/oversized transport and credential filtering. **No real Telegram account was contacted or message sent.**

## Review, failures and corrections

Task reviews corrected stale web completions, first-page-only history recovery and the A→B→A explicit-retry ownership race. One whole-M6 review then found optional MCP discovery could block login. Its consolidated correction also resolved hidden login errors and whitespace-only photo captions; the sole scoped final rereview cleared all three.

Final acceptance subsequently exposed a real Telegram shutdown race: a transport await could consume cancellation, leaving the unconditional polling loop alive while close waited indefinitely. The interrupted coverage attempt is retained with 106 passes, one skip and exit 2. Bounded task traces reproduced five stalls before any edit. Explicit closing guards and cancellation settlement now prevent another intake/delivery cycle and finish owned cleanup before propagating caller cancellation. Four deterministic regressions failed before the correction and passed afterward; 88 covering Telegram cases and twenty unassisted repeated coverage trials passed. A separate narrow lifecycle review approved the correction. Watchdog-assisted pre-fix completions and initial inconclusive diagnostic probes are recorded as reproduction evidence, never accepted passes.

The walkthrough also exposed two controller-helper mistakes, both retained: a symlinked macOS `/var` temporary docs path correctly rejected by MCP, and iteration over a shrinking `:checked` locator set that stalled before model submission. Canonicalizing only the owned helper path and iterating stable locators corrected them without production changes. The next attempt completed Qwen but found automatic favicon 401 console errors; a new browser RED/GREEN regression and embedded local favicon fixed that, followed by a narrow CSP/asset review. The full final source gates were refreshed after the production corrections. No broad review was repeated and no required finding was waived.

All review/ledger Markdown was archived and verified byte for byte before SDD removal. **No controller architecture rulings were required.**
