# HyperClaw Runtime v2 M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a small local chat runtime with durable runs, replayable streams, explicit cancellation, and authenticated HTTP/CLI access.

**Architecture:** Replace the old package in this isolated branch with src/hyperclaw. One daemon owns a concrete SQLite store, one Ollama transport, and one run worker; adapters submit and observe the same operations.

**Tech Stack:** Python >=3.11, sqlite3/tomllib/asyncio, httpx, Pydantic, FastAPI/Uvicorn, Typer/Rich, pytest, coverage, uv.

**Spec:** [Runtime v2 design](../specs/2026-09-09-runtime-v2-design.md), M1 scope in the [roadmap](2026-09-09-runtime-v2-roadmap.md).

## Global Constraints

- Python >=3.11; CI on Python 3.11 and 3.13; initial runtime support is macOS and Linux.
- One installable package at src/hyperclaw and one CLI entrypoint: hyperclaw.
- One daemon owns each runtime root, its SQLite connection, model requests, and tool processes.
- Default runtime root is ~/.hyperclaw-v2; default HTTP listener is 127.0.0.1:8011.
- Default model is qwen3.8:27b-mlx at http://127.0.0.1:11434; no cloud fallback or automatic model download.
- Existing ~/.hyperclaw data, .engram, other worktrees, and running services are outside the refactor's mutation scope.
- No old HTTP routes, import paths, environment aliases, database formats, or dashboard feature parity are required.
- Persistent side effects must pass through the execution policy and have a recorded invocation.
- Client disconnect does not cancel a run; cancellation is an explicit operation.
- Unknown tool outcomes are recorded as uncertain and are never automatically retried.
- Offline tests use temporary roots and loopback fixtures; real Ollama and Docker tests require explicit selection.
- Imported skills, retrieved text, and model output cannot grant execution authority.

## Public contracts

Define these in contracts.py using frozen Pydantic models with extra fields forbidden. Names and fields below are the contract used by all tasks.

| Type | Fields |
| --- | --- |
| Session | id: str; generation: int |
| RunRequest | session_id: str; generation: int; request_id: str; text: str; retry_of: str or None = None |
| Failure | code: str; message: str |
| Run | id: str; request: RunRequest; status: RunStatus; output: str or None; error: Failure or None; verification: literal not_requested |
| RunStatus | queued, running, succeeded, failed, cancelled, interrupted |
| RunEvent | run_id: str; seq: int; kind: str; at: UTC datetime; data: dict[str, JSON value] |
| Message | role: literal user or assistant; content: str |
| ModelEvent | kind: literal text, thinking, usage, finish; data: dict[str, JSON value] |

Terminal states are succeeded, failed, cancelled, interrupted. Model text/thinking data is {"text": "a received chunk"}; usage data contains model, input_tokens, output_tokens, with unknown counts represented by null, not zero. Finish data contains stop_reason. An Ollama stream is finished only after message_stop, with a valid final stop_reason. In M1 only end_turn is successful; max_tokens becomes output_limit, and tool_use becomes tools_disabled.

Exceptions: InvalidRequest, NotFound, Conflict, RootInUse, UnsupportedSchema, ProviderFailure, StorageFailure. Each carries a stable code and sanitized message. No provider credentials, tokens, or raw exception object enters an API response.

Settings in config.py has root: Path, ollama_url: str, model: str, thinking: bool, max_output_tokens: int, request_timeout_s: float, run_timeout_s: float, port: int. Defaults and limits are in the design. load_settings(root: Path | None = None, overrides: dict | None = None, environ: Mapping[str, str] | None = None) returns Settings without writing. initialize_root(settings: Settings) creates explicit config/token/workspace files without overwriting existing ones. ensure_root(root: Path) -> None is shared by setup and Store.open: create a marker containing format version 2 only in an empty/new root, or validate the existing marker. Refuse nonempty unmarked roots and known v1 configuration. This helper does not load settings or open the database.

Store in store.py exposes these async operations:

- open(root: Path) -> Store (classmethod); close() -> None.
- create_session() -> Session; get_session(session_id: str) -> Session; reset_session(session_id: str, generation: int) -> Session.
- submit(request: RunRequest) -> Run; get_run(run_id: str) -> Run.
- next_run() -> Run | None (atomically choose oldest queued run and mark running).
- append(run_id: str, kind: str, data: dict) -> RunEvent.
- events(run_id: str, after: int = 0, limit: int = 100) -> list[RunEvent].
- history(session_id: str, generation: int) -> list[Message] (only complete successful turns).
- finish(run_id: str, status: RunStatus, output: str | None = None, error: Failure | None = None) -> Run.
- recover() -> list[Run] (mark previously running runs interrupted before worker startup).

Store is concrete, not an abstract repository. Invalid terminal transitions fail, while repeated finish of an already terminal run returns its existing result without another event. Cancellation racing with completion therefore has one committed winner. submit checks request ID/payload before the busy-session rule, so retrying an existing request remains idempotent. Generation mismatch always conflicts. If retry_of is supplied, require an existing failed/cancelled/interrupted run in the same session and generation; a running or unrelated source cannot be retried through that link.

Ollama(settings: Settings) in ollama.py exposes stream(messages: list[Message], system: str = "") -> AsyncIterator[ModelEvent] and aclose() -> None. Use the actual HTTP fixture for tests, with the real transport.

Runtime(store: Store, ollama: Ollama, settings: Settings) in runtime.py takes ownership of these dependencies after start(). Its public async methods are start(), close(), create_session(), get_session(session_id), reset_session(session_id, generation), submit(request), get_run(run_id), and cancel(run_id). Their return types match Store; cancel returns Run. events(run_id: str, after: int = 0) is an async iterator of RunEvent that ends after the committed terminal event. close settles worker/model work and closes Ollama then Store. Startup failure closes any dependencies it acquired.

import pytest
from hyperclaw.config import load_settings
from hyperclaw.contracts import RunRequest
from hyperclaw.ollama import Ollama
from hyperclaw.runtime import Runtime
from hyperclaw.store import Store
from tests.support.provider import MODEL, ProviderStub, Reply

@pytest.mark.asyncio
async def test_completed_run_replays_after_restart(tmp_path):
    peer = ProviderStub()
    peer.enqueue(Reply(chunks=("Hello ", "world.")))
    settings = load_settings(root=tmp_path, environ={}, overrides={
        "ollama_url": peer.url, "model": MODEL,
    })
    first = Runtime(await Store.open(tmp_path), Ollama(settings), settings)
    await first.start()
    try:
        session = await first.create_session()
        run = await first.submit(RunRequest(
            session_id=session.id, generation=0, request_id="first", text="hello"))
        seen = [event async for event in first.events(run.id)]
        assert seen[-1].kind == "run.finished"
        assert seen[-1].data["status"] == "succeeded"
    finally:
        await first.close()
    second = Runtime(await Store.open(tmp_path), Ollama(settings), settings)
    await second.start()
    try:
        replayed = [event async for event in second.events(run.id)]
        assert [e.model_dump() for e in replayed] == [e.model_dump() for e in seen]
        assert (await second.get_run(run.id)).output == "Hello world."
    finally:
        await second.close()
        peer.close()
