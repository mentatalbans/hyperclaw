## Global constraints

- Python >=3.11; CI on Python 3.11 and 3.13; initial runtime support is macOS and Linux.
- One installable package at src/hyperclaw and one CLI entrypoint: hyperclaw.
- One daemon owns each runtime root, its SQLite connection, model requests, and tool processes.
- Default runtime root is ~/.hyperclaw-v2; default HTTP listener is 127.0.0.1:8011.
- Default model is qwen3.8:27b-mlx at http://127.0.0.1:11434; no cloud fallback or automatic model download.
- Existing ~/.hyperclaw data, .engram, other worktrees, and running services are outside the refactor's mutation scope.
- No old HTTP routes, import paths, environment aliases, database formats, or dashboard feature parity are required.
- Persistent side effects must pass through the execution policy and have a recorded invocation.
- Client disconnect does not cancel a run; cancellation is an explicit operation.
- Unknown tool outcomes are recorded as uncertain and are never automatically retried.
- Offline tests use temporary roots and loopback fixtures; real Ollama and Docker tests require explicit selection.
- Imported skills, retrieved text, and model output cannot grant execution authority.

## Concrete M4 decisions

The approved architecture is already explicit: lexical retrieval first. FTS5 is available in the installed SQLite. Use SQL scope/status/validity predicates before ordering and LIMIT; never retrieve global top five and then filter in Python. BM25's corpus statistics remain global to the active index, so this is a scoped candidate set, not a claim of independent per-session ranking statistics. See [SQLite FTS5](https://www.sqlite.org/fts5.html) for MATCH quoting, ascending BM25 and transactional index maintenance.

`MemoryScope(workspace_id, session_id=None)` means workspace visibility when session_id is absent, session visibility otherwise. A search with a session sees that session plus explicitly shared workspace records; a workspace-only search sees workspace records only. Mutation requires exact scope equality: changing a shared fact requires explicit workspace scope. Inaccessible IDs produce NotFound. Session reset clears conversation history but retains explicit session memory; new sessions remain isolated. There is no automatic promotion or memory extraction.

`MemoryRecord` includes id, scope, text, source_run_id, observed_at, valid_until, supersedes, version and status (`active`, `superseded`, `forgotten`). Each correction creates a new immutable text/version record with a new ID and supersedes the selected active version. Concurrent corrections of the same ID produce one winner; stale IDs conflict. Forget marks the selected active record forgotten, removes it from retrieval and is idempotent for that forgotten ID. Old versions/receipts remain inspectable evidence; forget is not archive erasure. An expired active record may be explicitly corrected into a new valid version.

Text is nonblank and at most 2,048 UTF-8 bytes, with no NUL; query is nonblank and at most 1,024 UTF-8 bytes. Search limit is a strict integer from 1 through 5. Times require an offset, normalize to UTC at fixed microsecond precision, and remain in years 1970–9998. `valid_until`, when present on a new version, must exceed observed_at; retrieval excludes records at or beyond expiry. A supplied source_run_id must exist and match the session scope and checkpoint workspace when those are present. Tool provenance is always derived from its actual run.

Public interfaces (extra keywords preserve the roadmap's positional interfaces):

```python
Memory(store, *, clock=utc_now)
await memory.remember(scope, text, source_run_id=None, *, valid_until=None)  # MemoryRecord
await memory.search(scope, query, limit=5)  # list[MemoryRecord]
await memory.correct(record_id, text, scope, *, source_run_id=None, valid_until=None)  # MemoryRecord
await memory.forget(record_id, scope)  # None
await memory.invoke(invocation_id)  # ToolReceipt; added in Task 2
```

Memory's synchronous private operations run only via `Store._call`, under `Store._transaction` for mutations. They are reusable inside the invocation transaction. Do not create another connection, owner, worker, cache or broker. An additive schema 4 creates record and FTS tables, scope/status indexes and transactional insert/update triggers. Only active versions are indexed; SQL still checks status and validity defensively. Expired index entries are excluded before LIMIT without a new expiry worker.

Queries are literal text, not an exposed MATCH language: tokenize bounded Unicode words, quote each safely, combine with OR, and use deterministic row-order tie breaking. Punctuation-only queries yield no matches. No stemming expansion, synonym map, stopword tuning, embedding index or paraphrase threshold is added before measuring the fixed fixture.

Four tool names are `memory_remember`, `memory_search`, `memory_correct`, `memory_forget`. Their schemas accept `scope: session|workspace` defaulting to session; they never accept workspace_id, session_id or source_run_id from the model. Remember/correct also accept text and optional valid_until; search accepts query/limit; correct/forget accept record_id. Runtime derives identity from the invocation's workspace and run. Memory is an admitted scoped capability when offered by the operator's run allowlist; it does not confer filesystem write or command grants. Existing approvals and command mount rules remain unchanged.

New runs and schedules offer the four memory tools in addition to M3's five tools. Historical stored run/schedule tool lists remain unchanged. Extend the existing `--tool` enum; no additional memory daemon, automatic context injection, operator CRUD routes or standalone memory command group is required. Memory results use existing tool receipts and grouped tool_result messages. Enforce the existing serialized receipt output bound; search may retain fewer leading complete records to fit, and must never truncate JSON or record text. A successful storage operation is not verification that a remembered statement is true.

```python
def perform():
    invocation = store._invocation(invocation_id)
    if invocation.receipt:
        return invocation.receipt
    receipt = self._invoke(invocation)
    return store._complete_invocation(receipt)
return await store._call(lambda: store._transaction(perform))
```
