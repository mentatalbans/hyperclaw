**Goal:** Ship one admitted, isolated documentation MCP integration and explicit reviewed instruction packages, with run provenance and measured interoperability.

## Global Constraints

- Python >=3.11; CI on Python 3.11 and 3.13; initial runtime support is macOS and Linux.
- One installable package at src/hyperclaw and one CLI entrypoint: hyperclaw.
- One daemon owns each runtime root, its SQLite connection, model requests, and tool processes.
- Default runtime root is ~/.hyperclaw-v2; default HTTP listener is 127.0.0.1:8011.
- Default model is qwen3.8:27b-mlx at http://127.0.0.1:11434; no cloud fallback or automatic model download.
- Existing ~/.hyperclaw data, .engram, other worktrees, and running services are outside the refactor's mutation scope.
- No old HTTP routes, import paths, environment aliases, database formats, or dashboard feature parity are required.
- Persistent side effects must pass through the execution policy and have a recorded invocation.
- Client disconnect does not cancel a run; cancellation is an explicit operation.
- Unknown tool outcomes are recorded as uncertain and are never automatically retried.
- Offline tests use temporary roots and loopback fixtures; real Ollama and Docker tests require explicit selection.
- Imported skills, retrieved text, and model output cannot grant execution authority.

## Verified dependency and boundary decisions

The [tagged SDK release](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.0.0) and a disposable installed `mcp==2.0.0` were inspected on 2026-09-10. The SDK owns JSON-RPC dispatch, types, negotiation, requests, errors and cancellation. `Client(transport, mode="auto", cache=None, input_required_max_rounds=0, read_timeout_seconds=...)` accepts an async context manager yielding SDK message streams. Its `mode="legacy"` negotiates handshake-era peers; assert the actual negotiated revision in tests. A modern pinned mode can avoid negotiation, so the acceptance fixture must additionally observe actual modern request metadata/discovery and legacy initialize traffic. Do not count merely constructing a client as protocol coverage. Published references: [2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28), [2025-11-25 lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

The SDK's stock stdio reader accumulates an unbounded line before parsing. Use its supported custom-transport interface for the owned Docker attachment: bound byte framing before SDK parsing, use the SDK `jsonrpc_message_adapter`/`SessionMessage` types, and let SDK Client implement the protocol. This is a transport/resource boundary, not another JSON-RPC implementation. No custom negotiation, IDs, dispatcher, retry engine or protocol models. A maximum 262,144-byte wire frame and a 65,536-byte complete serialized tool result are enforced independently. Drain/cap stderr and fail closed on malformed, disconnected, oversized or unsupported result types. No server sampling, roots, elicitation, tasks, subscriptions or remote auth are enabled. Cache is disabled and calls are never automatically retried. The SDK Client defaults to retrying modern InputRequiredResult responses; explicitly set input_required_max_rounds=0 (or use the documented session.call_tool with allow_input_required=True and reject that result) and test a state-only InputRequiredResult produces exactly one tools/call.

The MCP server identity is fixed as `docs`; model-facing names are `mcp_docs_search` and `mcp_docs_read`. They are explicit opt-in names, not added to DEFAULT_TOOLS. Operator-owned argument models define schemas and capability `mcp_docs`; server annotations and descriptions never authorize a call. Before `tools/call`, remote names/input/output schemas must match the reviewed expected catalog, not merely a permissive annotation. Changed catalog/image/documents/protocol requires renewed admission; pending checkpoints and approvals cannot reuse a changed fingerprint.

Use the same Docker installation/invocation labels and lifecycle. Each invocation gets one temporary peer container, created and bound durably before it starts; attach over stdin/stdout. Only the admitted documentation snapshot is mounted read-only at `/docs`. Never mount the workspace, runtime root/database, operator home, credentials or Docker socket. Retain unprivileged identity, no network, read-only root, dropped capabilities, no-new-privileges, bounded CPU/memory/PIDs/tmpfs/logs. Docker CLI attachment runs on the host; the server runs inside Docker. Closing the attachment is not evidence of container termination: inspect/terminate/remove through the existing owner before a conclusive receipt. Startup reconciliation must work even when the optional MCP extra or current peer configuration is absent.

## Task 1: Explicit reviewed skills and durable run provenance

**Files:** create `src/hyperclaw/skills.py`, `tests/unit/test_skills.py`, `tests/integration/test_skills.py`, `examples/skills/documentation-answer/SKILL.md` and a small referenced text resource; extend contracts.py, store.py, runtime.py, api.py, cli.py and relevant migration/context tests.

**Consumes:** Store._call/_transaction, immutable Value contracts, existing authenticated API/CLI, Checkpoint and Ollama.stream(system=...).
**Produces:** `Skills(directory: Path).load(name: str) -> SkillDocument`; SkillDocument(name, description, body, content_hash, resources), with immutable resource values (path, text, sha256). `Store.admit_skill(document)`, `Store.skill_admissions()`, `Store.admitted_skill(name, content_hash)` operate through the sole Store owner. `RunRequest.skills: tuple[str,...] = ()`; server-owned `Run.skill_hashes: dict[str,str] = {}` persisted in an additive runs column and optional bounded checkpoint skill instruction/provenance fields default empty for historical records. Extend `Store.submit(request, *, skill_hashes=None)` to atomically bind server-resolved selected hashes with admission validation; existing no-skill callers remain unchanged. Public `GET /v1/skills`, `GET /v1/skills/{name}`, `POST /v1/skills/{name}/admit` (expected content_hash), `DELETE /v1/skills/{name}/admission`; CLI `skill list/inspect/admit/revoke` and repeated `chat --skill NAME`.

Skills are read only beneath `root/skills/<name>/`. Name is lowercase letters/digits/hyphens, 1–64 characters, with no leading/trailing hyphen or consecutive hyphens. This is an explicitly documented narrow SKILL.md subset: UTF-8 YAML front matter with exactly single-line `name` and `description`, plus nonempty Markdown body. Accept plain or JSON-double-quoted scalar values; reject unsupported YAML constructs, extra metadata keys (including hooks/allowed-tools), duplicate fields, NUL and mismatched name. Description <=1,024 UTF-8 bytes; SKILL.md <=16,384 bytes; at most 16 referenced UTF-8 .md/.txt resources, each <=16,384 bytes; combined document+resources <=32,768 bytes. Body may reference local text via ordinary Markdown links. External HTTP(S) citations remain text and are never fetched. Reject absolute, parent, percent-encoded escape, backslash, file URI, symlink/hardlink/nonregular references and escaping directory components. Reject executable hooks or executable/nontext payloads in the package; unreferenced files are not executed or injected. Cap package traversal at 512 entries and depth 16. Use descriptor-relative reads and bounded traversal, not resolve-prefix checks alone. Changes to loaded metadata/body/resources change a canonical content hash.

Admission is explicit operator administration: preview returns the concrete document and hash; admit requires the exact hash just inspected and persists an immutable version and current admission in additive schema 5. Revoke removes current admission, retaining version evidence. No model tool exposes admission. Changing any loaded content requires re-admission for a new execution. Keep a loaded run's instruction snapshot and hashes in its checkpoint; resuming an approval uses that snapshot, not newly read instructions. Recheck that selected snapshot hashes remain admitted before further model/tool work; revoke or replacement admission blocks continuation rather than silently switching versions. Skill selection does not alter the tool allowlist or grants. Bind selected admitted hashes at submit, and verify those hashes again when first creating a run's execution context; a queued run whose selected skill changed before execution fails rather than silently changing instructions. Existing stored requests/checkpoints default to no skills.

Use Ollama's separate system text field for explicitly selected reviewed instructions, clearly framed as task guidance. Include system bytes in context budget selection and repeated-round bounds; reject over-budget instructions rather than silently truncating them. Do not store instruction text in normal user/assistant history or automatically carry it into later unselected runs. Record selected hashes and combined context hash/size in run.context; existing no-skill behavior remains unchanged. Tool-schema/config/model/workspace observations remain present. The document/resource hashes describe the selected instruction package, not an entire filesystem snapshot. At most 4 distinct skills may be selected per run. Schedules remain unchanged and use no skill selection in this milestone.

**Files:** create `src/hyperclaw/mcp.py` (client/admission integration), `src/hyperclaw/mcp_transport.py` (bounded owned attachment only), `examples/mcp-docs/{server.py,Dockerfile,README.md}`; add `tests/unit/test_mcp.py`, `tests/integration/test_mcp.py`, `tests/live/test_mcp.py` and bounded SDK fixture peers/support as needed. Extend pyproject.toml/uv.lock, contracts.py, config.py, store.py, execution/{__init__,policy,docker}.py, runtime.py, api.py, cli.py, optional-extra CI/verification installation commands, Makefile, scripts/test_battery.py, tests/conftest.py and tests/unit/test_battery.py.

**Consumes:** existing Executor/Policy/Store invocation and Docker create/bind/terminate/reconcile contracts, Task 1 context snapshots/provenance.
**Produces:** `McpTools(store, settings, backend).list_tools() -> list[ToolDefinition]` (reviewed definitions, no server start); `McpTools.invoke(call: ToolCall, *, invocation_id: str) -> ToolReceipt` through an already persisted/admitted Executor invocation; methods `inspect_admission()`, `admit(expected_sha256)`, `revoke()` for authenticated operator administration. `ToolDefinition` is an immutable value with model-facing name/description/input_schema and effective capability/effect bounds. Keep existing Executor definition dictionaries for Ollama by converting at that boundary. `Store.admit_mcp(manifest)`, `Store.mcp_admission()`, `Store.revoke_mcp()` add schema 6 with immutable historical manifest evidence and current admission.

Optional settings are `mcp_docs_path: str = ''`, `mcp_docs_image: str = ''`, `mcp_protocol: Literal['2026-07-28','2025-11-25'] = '2026-07-28'`. Empty path/image disables the integration; require both together. Image must be a resolved sha256 image ID or repository@sha256 digest, never a mutable tag. Do not contact a model, Docker, peer or package index during ordinary config/init/doctor or chat without MCP selection. Missing optional dependency yields a clear MCP-unavailable error when used, while base chat/skills/memory and startup cleanup still work. The example image is built explicitly from a digest-pinned Python base using the reviewed locked dependencies and shipped server, with no installation/download on runtime startup. Record the actual built image digest and source hashes during acceptance.

Documentation source is an explicit absolute directory. Reject source roots overlapping the runtime root or operator home in a way that includes protected data. Bounded descriptor-relative collection admits only .md/.txt public text, at most 512 files, each <=65,536 bytes and combined <=8 MiB; reject symlinks/hardlinks/nonregular files and unsafe paths. Skip other regular extensions without reading them. Preview presents file hashes and catalog/image/protocol policy fingerprint. Admit requires that exact fingerprint, publishes a validated immutable snapshot beneath `root/mcp-docs/<content_hash>/` and records the manifest through Store; never expose the enclosing runtime directory. Recheck snapshot identity/integrity before dispatch. Failed staging/admission cannot partially authorize a new peer. Existing snapshots and admission evidence survive revoke/restart; no broad GC is introduced. Content snapshot hash is the relevant documentation revision recorded on runs/receipts, without claiming a full workspace snapshot.

Operator schemas are a closed read-only pair: `search(query: str, limit: int=5)` with nonblank query <=256 UTF-8 bytes and strict integer limit 1–5; `read(path: str, start_line: int=1, max_lines: int=80)` with a safe relative .md/.txt path <=512 bytes, strict positive start_line and max_lines 1–200. Remote names are `search`/`read`, namespaced model names `mcp_docs_search`/`mcp_docs_read`. Server results carry source paths, line information and observed full-file hashes, with bounded excerpts (<=8,192 UTF-8 bytes per read, <=512 bytes per search hit) and whole JSON output. The server uses maintained SDK server dispatch and the same reviewed schemas; no host execution, writes, arbitrary resources, URLs or credentials. Exact expected server tool metadata/schemas are included in admission; unreviewed additions/changes fail before tools/call. Standard optional result features outside the supported text/structured JSON subset fail explicitly.

Admission APIs are `GET /v1/mcp`, `POST /v1/mcp/admit` with expected_sha256, `DELETE /v1/mcp/admission`; CLI `mcp inspect/admit/revoke`. Preview and admission do not start a peer. Tool selection adds the two closed names to allowed (not default) tools and the CLI enum. Policy uses persisted admission/current fingerprint and canonical operator schemas; MCP receives no general write/execute grant. Compare checkpoint admission fingerprint before model rounds and dispatch, and include it in policy hashes. Revoke/schema/content/image changes prevent old pending work from dispatching. No model-facing admission/configuration route exists. MCP tool selection in M5 is supported for directly submitted runs, including detached runs. Schedule creation must reject the two MCP names with a clear validation error; existing scheduled tool choices remain unchanged. Scheduled admission/revocation binding is deferred explicitly, rather than accepting schedules that cannot enqueue safely.
